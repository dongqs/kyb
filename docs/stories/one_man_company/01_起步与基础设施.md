# 起步与基础设施

## 100 Agent 自动迭代

启动一个 100 个 agent 自动迭代的项目，发现瓶颈在编译速度。

## 关键是需要 CI/CD

编译瓶颈实际上是 CI/CD 流水线的吞吐量瓶颈。解决方案分层：

1. **快速见效** — 换用极速链接器（mold/lld）、编译缓存（ccache/sccache）、并行编译
2. **增量/按需** — 只编译被修改的模块、语法级预筛选、后台异步编译队列
3. **跳过编译** — 脚本化或解释执行，或编译为 Wasm
4. **分布式编译** — distcc/icecream 集群

## 语言选型：Go vs Python

1 万行规模 + 100 Agent 迭代 + CI/CD 强制：

| 语言 | 编译时间 | Agent 友好度 | 适用场景 |
|------|---------|-------------|---------|
| Python | 0 秒 | 最高，动态类型 LLM 出错少 | 迭代速度优先 |
| Go | 0.5-2 秒 | 强类型需多轮修正 | 长期运行、部署方便 |
| Rust | 5-20 秒 | 低，借用检查器易错 | 不推荐 |

结论：**Go 足够快**，单次编译 1-2 秒不是问题，真正瓶颈是 CI 排队和缓存未命中。Python 更快但运行时性能低。

## 全上云 / 无限 K8s

核心思路：每个 Agent → 独立临时 Pod → 编译+测试 → 结果返回。100 个 Pod 并行，总耗时 10-12 秒。

关键设计：
- 代码分发：浅克隆或挂载共享 PVC
- 依赖缓存：分布式缓存卷（EFS/Filestore）
- 结果收集：对象存储（S3/MinIO）
- 预热 Pod 池减少启动延迟

**无限 K8s 改变游戏规则**：不再被单机编译速度束缚，大胆用 Go。
