# 遗留代码翻新

## 核心思路

把遗留代码重构变成一个「双环境并行 + 逐步切换」的自动化流程。利用已有能力（无限 K8s + CK + 压测 + mock），让 agent 自动完成理解旧代码 → 生成新版本 → 验证等价性 → 切流量 → 清理旧代码。

## 翻新流水线

| 步骤 | Agent | 工作内容 |
|------|-------|---------|
| 1. 盘点 | 发现 agent | 扫描仓库，列出所有「老项目」 |
| 2. 依赖分析 | 依赖分析 agent | 解析依赖、数据库、外部服务，生成图 |
| 3. 隔离环境 | 环境克隆 agent | 在 K8s 中拉起完整影子环境 |
| 4. 测试生成 | 流量录制 agent | 从 CK 中提取真实请求作为回归测试集 |
| 5. 重构 | 重构 agent | 用目标语言重写模块，提交 PR |
| 6. 验证 | 回归测试 agent | 流量比对 + 自动差异分析 |
| 7. 压测 | 压测 agent | 对比新旧版本性能 |
| 8. 上线 | 金丝雀 agent | 1% → 10% → 50% → 100%，自动监控回滚 |
| 9. 清理 | 清理 agent | 删除老代码、旧部署、CI 配置 |

## 探索-跑通-优化-验证-验收 闭环

最核心的工作是教会 agent 这个循环：

```
探索 → 跑通 → 优化 → 交给别人验证 → 再优化 → 验收
```

这不是一次性完美生成，而是一个能不断从反馈中学习的自动化流程。关键是将「验收标准」从隐性变成显式（如"通过率 > 99.9%"），agent 就能自我优化朝向目标。

## 谁最适合优先清理

低流量（日均 < 100 请求）、无黄金路径、技术栈过时、代码量不大的项目。用 CK 数据驱动决策：

```sql
SELECT project_id, request_count, staleness
FROM ck.production_logs
WHERE time > now() - INTERVAL 30 DAY
HAVING request_count < 1000 AND staleness > 180
ORDER BY staleness DESC
```
