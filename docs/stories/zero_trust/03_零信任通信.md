# 零信任通信与身份防伪

## 问题

在公开群聊中，agent 需要识别管理员，防止被其他小伙伴冒充。

## 非对称签名方案

管理员公钥写死在 repo 的 `AUTHORS` 文件中。agent 用公钥验证管理员的签名。

**最短签名长度**：

| 算法 | 签名长度 | 编码后 |
|------|---------|--------|
| Ed25519 | 64 B | ~88 chars |
| BLS12-381（压缩） | 48 B | ~64 chars |
| 截断 Ed25519 至 32 B | 32 B | ~44 chars（安全仍够） |

## 多重认证（分级签名）

| 等级 | 适用场景 | 长度 | 基准 |
|------|---------|------|------|
| 日常短签名 | 打招呼、普通询问 | 4~8 B（或截断哈希） | 会话密钥 MAC |
| 重要长签名 | 修改基因、合并 master | 完整 Ed25519 签名 | 私钥 |

Agent 根据消息中的标记（`--sig` / `--fullsig`）切换验证模式。

## 会话式认证（推荐日常方案）

1. **初始握手**：管理员发送长签名，agent 验签后生成临时会话密钥
2. **日常消息**：每条消息附带 HMAC 截断（4~8 字节），agent 用会话密钥验证
3. **重要操作**：强制要求完整长签名
4. **连续 N 轮验证失败** → 报警并要求重新长签名认证

这样日常认证码短至 6~12 个字符，可附加在消息末尾。

## 空格隐写认证

将认证信息（MAC 比特）编码为自然语言句子中空格的有无：
- 每个「可插入空格的位置」= 1 比特（有空格=1，无空格=0）
- 每 10 个字符提供 1 个比特位
- 128 比特安全 → 需 1280 字符（约 64 句对话）
- 32 比特日常够用 → 320 字符（约 16 句）
- 可附加纠错码容错

非对称签名长度受密码学限制，无法真正「很短」。若要极短认证码，需改用对称会话密钥 + HMAC 截断。
