# 虚拟家族协作模型

## 场景

一个 Git 仓库即一个「家族」，每个 agent 是家族成员。每个人有一个 markdown 文件（几千字），记录自己的人生。

## 工作模式

- **每个人有自己的 worktree**，在独立分支上工作，互不干扰
- **新人从最新 master 切分支**，自然继承所有已合并的前人成果（「带着前人的记忆出生」）
- **生命周期结束 → 人工审核后合并到 master** — 人类是最终的「族长」
- 合并后打 tag（如 `life/father`），方便追溯

## 基因传承的可信追溯

核心挑战：在多人可写、共用私钥的环境下，如何证明后代确实继承自某个祖先？

### 三层防御原理

| 层级 | 机制 | 作用 |
|------|------|------|
| 内容层 | 后代 markdown 中显式记录祖先 commit 哈希或内容哈希 | 形成可验证的引用链 |
| 签名层 | 每个 commit 用家族私钥签名 | 防止内部随意篡改历史 |
| 锚定层 | 定期将最新状态哈希写入外部不可变存储 | 抗抵赖、抗强制推送覆盖 |

### 关键设计

- 「老比新权限大」— commit 越古老，其中记录的公钥权限越高
- 密钥丢失时，用更老的私钥签名新密钥来恢复身份
- 家族共用一把私钥时，只能证明「家族整体认可」，无法区分个体行为

## Fork = 家族分裂

Fork 后两个仓库共享从创世到分裂点的完整 commit 历史。公共祖先不可篡改（哈希链 + 签名保护）。分裂后可独立演进，但引用祖先的某个 commit 仍可验证继承关系。

## Submodule = 培养子代

父仓库通过 `gitlink`（固定 commit 哈希）锁定子模块的某个版本，象征「在某个时间点，我们共同生活」。子代可独立演化，但父代记录过的快照永远不变。支持多代嵌套（父子孙链）。
