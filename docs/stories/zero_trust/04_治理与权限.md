# 治理与权限体系

## 授权管理

管理员在 `AUTHORS` 文件中添加/撤销公钥，创建新的签名的 commit 即可：

- **授权**：添加公钥 → commit → agent 拉取后生效
- **撤销**：删除公钥或标记失效 → commit → agent 不再接受
- 每次授权和撤销都在 commit 历史中永久可审计

## Agent 间权限

| 模型 | 原理 | 适用 |
|------|------|------|
| 古老优先 | agent 首次出现的 commit 越古老，权限越高 | 祖辈权威 |
| 显式等级 | AUTHORS 中指定 level 字段，管理员签名 | 灵活调整 |
| 委托授权 | A 签名「授予 B 某权限」，B 凭签名向他人证明 | 去中心化 |
| 投票权重 | 按等级或贡献分配权重，用于集体决策 | 共治场景 |

所有权限变更都在 Git 不可变历史中，有签名保护。agent 独立验证对方的权限。

## Agent 短寿命（一周）

- agent 公钥附带有效期（`valid_from` / `valid_until`），由管理员签名
- 过期签名被自动拒绝，但 agent 在有效期内的历史记录仍不可篡改
- 跨分支引用需附带被引用方在有效期内的证明

## Agent 自管 master

将合并规则写入 `CONSTITUTION`（由创世私钥签名），合并权限委托给 Guardian agent：

- 多 agent 共治（委员会结构），合并需 N/M 签名
- 时间锁、熔断机制、任期轮值
- 人类可保留紧急覆写能力（否决密钥）

## AI 与人类共治

AI agent 通过投票共识决定「授予人类部分权限」：
- 提案 → 投票 → 结果写入 AUTHORS 或 CONSTITUTION
- 授权可以是临时的、范围限定的（如仅紧急停止权限）
- 人类行使权限的每个动作也留有签名记录
- 外部锚定提供最终安全网

## 宪法自治的演化路径

人类治家 → 监督模式（agent 自动合并但需人类确认）→ 半自动（低风险自动，核心规则需人）→ 完全自治（宪法 + Guardian）

最终走向「代码即法律」，信任从「人」转移到「可验证的规则」。
