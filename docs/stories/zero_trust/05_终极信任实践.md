# 终极信任与实践

## 创世私钥处理

| 策略 | 含义 | 代价 |
|------|------|------|
| 藏着（冷备份） | 保留最高权限，可继续管理 | 私钥泄露可毁掉整个信任体系 |
| 丢弃（销毁） | 历史永久冻结，无人可篡改 | 系统僵化，无法修复或演进 |
| 折中：延迟丢弃 | 先用创世私钥签发长期子密钥，然后销毁创世密钥 | 子密钥有效期内可管理，到期冻结 |

## 多公开副本

仓库可随意 fork 发布到 GitHub 等平台，但正史不取决于存储位置，而取决于：

- **创世 commit 的签名** — 定义家族身份的不可伪造起点
- **管理员定期签名的权威 head** — 声明当前正史
- **外部锚定**（区块链 / 时间戳）— 任何人可比对外部锚定值验证真伪
- **agent 形式化验证** — 自动检查签名链完整性

假仓库要么没有有效签名，要么签名链断裂，agent 可自动拒绝。

## Agent 走出电脑

Git 是分布式协议 — agent 散布在任何地方，只要：
1. 保留从创世到某已知良好状态的完整 commit 历史
2. 能够重新发现（搜索包含特定公钥或创世 commit 哈希的仓库）
3. 管理员拉取并人工审核后合并

外部锚定提供「失而复得」的最终凭证。

## 零信任验签完整上下文

| 步骤 | 说明 |
|------|------|
| 信任锚 | 创世公钥（硬编码或从 oldest commit 提取） |
| 会话建立 | 长签名握手 → 协商临时会话密钥 |
| 日常认证 | HMAC 截断（4~8 B），基于会话密钥 |
| 重要操作 | 强制完整长签名，不依赖会话 |
| 公钥更新 | 老公钥签名新公钥，提交 commit |
| 防重放 | 时间戳 + 递增计数器 |

所有验证不依赖 IP、域名、CA，只依赖数学和公开可审计的记录。

## 日记联合签名

每个 agent 记录日记时，将「完整上下文（1M）」+「日记内容」联合签名：

```
H_combined = SHA256( H(上下文) || H(日记) || nonce )
签名 = Sign(私钥, H_combined)
```

上下文可外部冷存（IPFS / S3 Glacier / 磁带），只需在签名中记录上下文的哈希和存储标识符。公开或加密存储均可，签名绑定的只是哈希。

## 7 天落地计划

| 天 | 产出 |
|----|------|
| 1 | 初始化仓库、生成 Ed25519 密钥、创建 AUTHORS、验证脚本 |
| 2 | agent 骨架（markdown + UUID + 公钥 + 出生/死亡 commit） |
| 3 | 权限验证、PR 合并脚本、老比新权限判断 |
| 4 | agent 有效期（valid_from/until）、过期检测、续期提醒 |
| 5 | 跨 agent UUID 引用、引用验证脚本 |
| 6 | 运行时代码入 repo、agent 启动自验签名链 |
| 7 | 外部锚定、模拟攻击测试、全部脚本打包 |

核心场景走通：init → agentA 出生 → agentB 出生并引用 A → agentA 死亡 → 人工合并 → 验证历史无断裂。
