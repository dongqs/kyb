# kyb-infra 服务流程

> 每件事的标准化操作流程。降熵、零信任、可回溯。

## 冷启动协议

每次新会话（容器重启、对话超时、新 agent 上线）都是白纸一张。
不要直接干活，先回答四个问题：

### 第零步：接引

```
1. 读 CLAUDE.md     ← 项目规范、当前分支、关键文件
2. 读 mr-tracker.md  ← 哪些 MR 开着、到哪一步了
3. 读 .kyb-diaries/ 最新日记 ← 上次在做什么、为什么停了
4. 跑一轮巡检        ← 四台机器现在什么状态
5. 汇报              ← "当前状态 + 下一步建议"
```

**你不在的时候，系统自己会跑。你回来的时候，流程帮你接上。**

### 启动检查清单

- [ ] 读 CLAUDE.md（项目 + 个人两份）
- [ ] 看 git status、当前分支
- [ ] 搜 MR tracker（`docs/infra/mr-tracker.md`）
- [ ] 读最新日记（`.kyb-diaries/` 按日期排序）
- [ ] 巡检四台机器（火山云/sim/nuc8/Mac）
- [ ] 确认上一件未完成的事项
- [ ] 汇报 + 等你指示

**没做完这些之前，什么活都不要开始。**

## 事分三等

| 等级 | 规模 | 流程 | 例子 |
|------|------|------|------|
| **S** | 一人一小时能闭环的 | 看→干→查 | 改个端口、加个 UFW 规则 |
| **M** | 涉及多个组件需设计 | 看→设计→审→干→查→存档 | 装 kyb CLI、部署 Grafana 仪表盘 |
| **L** | 跨系统架构变更 | 看→设计→审→试点→审→铺开→查→存档 | 迁集群、设计新服务 |

## 六步标准流（M/L 适用）

```
看  →  设计  →  审  →  干  →  查  →  存档
```

### 1. 看
派人了解现状。只看不动手。
输出：当前状态摘要 + 风险点。

### 2. 设计
出方案。包含：
- 背景：为什么做
- 选项：至少 2 个可选方案，含被否方案及理由
- 推荐：选哪个 + 理由
- 步骤：具体命令/配置
- 回滚：搞砸了怎么还原

### 3. 审
你看。你说"行"才往下走。

### 4. 干
派一路实施。严格按照设计方案执行，不改不扩。

### 5. 查
派三路独立验收，互不知道对方结论。全部 PASS 才算过。
任一路 FAIL → 回去修 → 再查一轮。

### 6. 存档
写 ADR，记：
- 什么决策、为什么、被否了什么
- 踩了什么坑
- 谁干的、谁查的

S 级事：看→干→查，不设计不存档。
M 级事：完整六步。
L 级事：看→设计→审→**试点→审**→铺开→查→存档（加试点环节）。

## 干活规则

```
永远不是"我觉得安全"，而是"三组独立专家都说安全"。
```

### 派活
- 一人干，三人查
- 干的不知道查的会查什么，查的不知道另一个查的查了什么
- 从不复用之前的 agent（每次派新的，防 contamination）

### 实施
- 不改设计方案（方案审过了就按方案来）
- 改方案先停，回来审，再审过再继续
- 每一步验证通过才下一步

### 验收
- 查的人不带任何上下文，纯从零看
- 结论必须明确：PASS / FAIL / 不确定
- 不确定 → 派十组交叉鉴定。还不确定 → 找你

### 止损
- 试了两下搞不定 → 停下，换人或另外设计
- 发现方案有根本问题 → 停下，回来重审
- 任何一步不确定 → 停下，找人

## 存档格式

每个 M/L 级事项在 `docs/infra/adr/` 或 `.kyb-diaries/` 留一条：

```
# ADR-日期-标题

## 决策
一句话说清选了哪个方案

## 为什么
关键的约束条件和理由

## 被否方案
其他方案及否决理由

## 踩坑
实际操作中遇到的问题

## 参与人
干: agent-id
查: agent-id, agent-id, agent-id
```

S 级事项不单独存档，在当天日记里带一笔就行。
