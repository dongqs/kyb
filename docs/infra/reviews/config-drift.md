# Design: Config Drift Detection for Infra Containers

**Design doc**: `docs/infra/reviews/config-drift.md`
**Reviewer**: kyb
**Date**: 2026-05-23
**Scope**: Multi-cluster infra container config tracking, drift detection, alerting, and remediation

---

## 1. Problem Statement

The multi-cluster infra runs `kyb-infra-boss` containers across three clusters (Mac/Orbstack, Aliyun, Office) plus `kyb-registry-cache` and other service containers. Each boss has a set of configuration files that define its behavior:

- `~/.config/kyb/config.yml` -- project config (proxy, registry_mirror, etc.)
- `~/.kyb/` -- project source code (entrypoint.sh, lib, etc.)
- Container-level configs (Docker health checks, env vars, volume mounts)

Currently, configs are deployed via git push + manual restart, but **drift accumulates silently**:

| Drift Source | Example | Frequency | Detection |
|---|---|---|---|
| `ssh sim` + manual `docker exec` edit | Operator tweaks `config.yml` directly | Weekly | None |
| Emergency hotfix without commit | `docker exec kyb-infra-boss sed -i ...` | Monthly | None |
| Incomplete rebuild after git pull | `git pull` but forgot `kyb build` | Bi-weekly | None |
| Container restart loses ephemeral config | Changes made with `docker cp` then container restarts | Quarterly | None |
| Divergent configs across clusters | Aliyun config updated, Mac forgotten | Monthly | None |
| Terraform/Ansible drift (future) | IaC state vs actual diverges | N/A | None |

### Impact

| Outcome | Scenario | Cost |
|---------|----------|------|
| **Silent config mismatch** | Mac boss uses `docker.xuanyuan.me`, but Aliyun boss still points to ACR that changed | Pull fails, builds stall |
| **Ghost configs** | Someone adds `--memory=4g` to a container via `docker update`, not in any deploy script | Next restart resets, surprise behavior change |
| **Undocumented hotfix** | `config.yml` edited on sim to add `no_proxy` entry for new service | Next `git pull` overwrites, revert to broken state |
| **Divergent CLAUDE.md** | `entrypoint.sh` updated in git, but boss container's generated CLAUDE.md is stale | Agent instructions out of sync |

**Goal**: Every config change -- whether intentional (deploy) or unintentional (drift) -- is detected, logged, and either auto-reverted or alerted.

## 2. Scope

### 2.1 What Config Is Tracked

| Layer | Files | Source of Truth | Drift Risk |
|-------|-------|-----------------|------------|
| **Config YAML** | `~/.config/kyb/config.yml`, `~/.config/kyb/clusters.yml` | Git (per-boss clone) | High -- frequently hand-edited |
| **Source code** | `~/.kyb/entrypoint.sh`, `~/.kyb/lib/*.rb`, `~/.kyb/bin/kyb` | Git (origin) | Low -- git manages these |
| **Generated files** | `~/.kyb/CLAUDE.md` (auto-generated by entrypoint.sh) | entrypoint.sh | Medium -- can be stale |
| **Container runtime** | `docker inspect` output (env vars, mounts, cmd, healthcheck) | Deploy script / `docker run` command | Medium -- `docker update` can drift |
| **Container entrypoint files** | `/usr/local/bin/*.sh` (patrol, watcher, heartbeat scripts) | Git + deploy script | Medium -- hand-edited during debugging |
| **System configs** | `/etc/hosts`, `/etc/resolv.conf`, `/etc/apt/sources.list` | Docker defaults | Low -- rarely changed in containers |

### 2.2 What Is NOT Tracked

| Item | Reason |
|------|--------|
| `/proc`, `/sys` filesystem | Kernel interface, not config |
| Docker overlay2 filesystem | Implementation detail |
| `~/.kyb/.git/` contents | Git internals, not configuration |
| Container journal / log files | Not config |
| Runtime-generated temp files | `/tmp/*`, session data |
| Secrets (`.env`, credentials) | Handled by separate secret management |

### 3.2 Components

#### Generator (`kyb config snapshot`)

A CLI command that computes SHA256 checksums of all tracked config files on the current boss and writes them to ClickHouse as a **baseline snapshot**. This runs:

- **After every `git pull` + deploy** (marks the new "clean" state)
- **On first boot** of a new boss container (establishes initial baseline)
- **On demand** via `kyb config snapshot` (manual baseline reset after intentional edit)

#### Detector (`kyb config check`)

A CLI command that computes current checksums and compares them against the **latest baseline snapshot** from ClickHouse. Differences are reported as drift events. This runs:

- **Every patrol cycle** (integrated into the 5-minute patrol)
- **On demand** via `kyb config check` (ad-hoc verification)
- **On container stop/restart** (via Docker event watcher trigger)

#### Baseline Storage (ClickHouse)

Three tables in the `infra` database:

1. `config_baselines` -- the authoritative "clean" checksums per boss per snapshot
2. `config_drifts` -- drift events (what changed, when, by whom if detectable)
3. `config_snapshots` -- periodic full snapshots (for trend analysis and forensics)

## 4. Checksum Strategy

### 4.1 Algorithm

SHA256 of each tracked file's contents. No symlink following (checksum the symlink itself).

```bash
# Compute checksum for a single config file
sha256sum ~/.config/kyb/config.yml
# Output: abc123def...  /home/dev/.config/kyb/config.yml

# Compute checksum for all tracked files (batch mode)
find ~/.config/kyb ~/.kyb/entrypoint.sh ~/.kyb/bin/kyb \
  -maxdepth 0 -type f 2>/dev/null \
  | xargs sha256sum
```

### 4.2 Why SHA256, Not md5sum or Git SHA

| Algorithm | Speed | Collision risk | Tool availability | Verdict |
|-----------|-------|----------------|-------------------|---------|
| SHA256 | Fast (100MB/s on modern CPUs) | Negligible | `sha256sum` in all base images | **Selected** |
| SHA1 (git) | Fast | Theoretical (SHAttered) | `sha1sum` / `git hash-object` | Acceptable but git-specific |
| MD5 | Faster | Practical collision possible | `md5sum` | Avoid (collision risk) |
| BLAKE2b | Fast | Negligible | Not always available in Alpine | Skip (availability concern) |

SHA256 is the best balance: universally available in the kyb base image (busybox/coreutils), fast enough for <10 files per container, and no collision concerns.

### 4.3 File Categories and Check Rules

Each tracked file has a **check rule** that defines what constitutes drift:

| Rule | Meaning | Example | Drift Severity |
|------|---------|---------|----------------|
| `exact_match` | File must match baseline byte-for-byte | `config.yml` | P2 (service degradation) |
| `git_committed` | File must match HEAD in git | `entrypoint.sh` | P2 (uncommitted change) |
| `permissions_match` | Permissions must match baseline | `bin/kyb` (must be 755) | P3 (info) |
| `template_match` | File must match the template that generates it | `CLAUDE.md` (vs entrypoint.sh template) | P3 (info) |

### 4.4 Baseline Generation Script

```bash
#!/usr/bin/env bash
# kyb-config-snapshot.sh — Generate and store config baseline
# Runs on boss container after deploy or on demand

set -euo pipefail

CK_URL="${CK_URL:-http://100.104.244.99:8123}"
BOSS_ID="$(hostname)"
CLUSTER="${CLUSTER_NAME:-unknown}"
SNAPSHOT_ID="$(date -u +%Y%m%dT%H%M%SZ)-${BOSS_ID}"

# Files to checksum (relative to HOME)
TRACKED_FILES=(
  ".config/kyb/config.yml"
  ".config/kyb/clusters.yml"
  ".kyb/entrypoint.sh"
  ".kyb/bin/kyb"
  ".kyb/lib/kyb/config.rb"
  ".kyb/lib/kyb/docker.rb"
  ".kyb/lib/kyb/container.rb"
  ".kyb/mise.config.toml"
  ".kyb/Dockerfile"
)

echo "=== Config Snapshot ${SNAPSHOT_ID} ==="
echo "Cluster: ${CLUSTER}, Boss: ${BOSS_ID}"

# Compute checksums
ROW_DATA=""
FIRST=true
for REL_PATH in "${TRACKED_FILES[@]}"; do
  FULL_PATH="${HOME}/${REL_PATH}"
  if [ ! -f "$FULL_PATH" ]; then
    echo "[SKIP] ${REL_PATH} — not found"
    continue
  fi

  CHECKSUM=$(sha256sum "$FULL_PATH" | cut -d' ' -f1)
  FILE_SIZE=$(stat -c%s "$FULL_PATH" 2>/dev/null || echo 0)
  FILE_MODE=$(stat -c%a "$FULL_PATH" 2>/dev/null || echo "644")

  # Check git status if applicable
  GIT_STATUS="unknown"
  if git -C "${HOME}/.kyb" status --porcelain "${REL_PATH#.kyb/}" >/dev/null 2>&1; then
    if git -C "${HOME}/.kyb" diff --quiet "${REL_PATH#.kyb/}" 2>/dev/null; then
      GIT_STATUS="committed"
    else
      GIT_STATUS="uncommitted"
    fi
  fi

  # Escape single quotes in REL_PATH for ClickHouse JSON
  SAFE_PATH=$(echo "$REL_PATH" | sed "s/'/\\\\'/g")

  ROW="{"
  ROW+="'boss_id': '${BOSS_ID}', "
  ROW+="'cluster': '${CLUSTER}', "
  ROW+="'snapshot_id': '${SNAPSHOT_ID}', "
  ROW+="'check_time': '$(date -u +%Y-%m-%dT%H:%M:%SZ)', "
  ROW+="'file_path': '${SAFE_PATH}', "
  ROW+="'checksum_sha256': '${CHECKSUM}', "
  ROW+="'file_size': ${FILE_SIZE}, "
  ROW+="'file_mode': '${FILE_MODE}', "
  ROW+="'git_status': '${GIT_STATUS}'"
  ROW+="}"

  if [ "$FIRST" = true ]; then
    ROW_DATA="$ROW"
    FIRST=false
  else
    ROW_DATA="${ROW_DATA}\n${ROW}"
  fi

  echo "[OK]   ${REL_PATH} → ${CHECKSUM} (${FILE_SIZE} bytes, mode ${FILE_MODE}, git: ${GIT_STATUS})"
done

# Store baseline in ClickHouse
echo ""
echo "=> Storing baseline snapshot to ClickHouse..."
echo -e "$ROW_DATA" | curl -s -X POST "${CK_URL}" \
  -d "INSERT INTO infra.config_baselines FORMAT JSONEachRow
$(echo -e "$ROW_DATA")" \
  --max-time 10 || echo "[WARN] Failed to store baseline"

# Also store a full snapshot (for forensic comparison)
echo "=> Storing full snapshot..."
curl -s -X POST "${CK_URL}" \
  -d "INSERT INTO infra.config_snapshots FORMAT JSONEachRow {
    'boss_id': '${BOSS_ID}',
    'cluster': '${CLUSTER}',
    'snapshot_id': '${SNAPSHOT_ID}',
    'snapshot_time': '$(date -u +%Y-%m-%dT%H:%M:%SZ)',
    'file_count': ${#TRACKED_FILES[@]},
    'snapshot_json': '$(echo "$ROW_DATA" | python3 -c "import sys,json; print(json.dumps(sys.stdin.read()))" 2>/dev/null)'
  }" --max-time 10 || echo "[WARN] Failed to store full snapshot"

echo "=== Snapshot ${SNAPSHOT_ID} complete ==="
```

### 4.5 Baseline Update Workflow

The baseline must be updated **after every intentional config change**:

```
git pull → kyb config snapshot   # Normal deploy: update source, then snapshot
kyb edit config                  # Interactive config edit tool (future)
  → kyb config snapshot          # Auto-snapshot after save
docker cp new-config.yml ...     # Emergency config push
  → kyb config snapshot          # Must be run manually after
```

To enforce this, the deploy script includes the snapshot call:

```bash
# In deploy.sh:
git pull origin master
kyb build  # if Dockerfile changed
# ... restart services ...
kyb config snapshot  # <-- mark new baseline
```

## 5. Drift Detection Mechanism

### 5.1 Detection Script

```bash
#!/usr/bin/env bash
# kyb-config-check.sh — Detect config drift
# Runs as part of the 5-minute patrol

set -euo pipefail

CK_URL="${CK_URL:-http://100.104.244.99:8123}"
BOSS_ID="$(hostname)"
CLUSTER="${CLUSTER_NAME:-unknown}"

# Files to check (same list as snapshot generator)
TRACKED_FILES=(
  ".config/kyb/config.yml"
  ".config/kyb/clusters.yml"
  ".kyb/entrypoint.sh"
  ".kyb/bin/kyb"
  ".kyb/lib/kyb/config.rb"
  ".kyb/lib/kyb/docker.rb"
  ".kyb/lib/kyb/container.rb"
  ".kyb/mise.config.toml"
  ".kyb/Dockerfile"
)

echo "=== Config Drift Check [${CLUSTER}/${BOSS_ID}] ==="
DRIFT_COUNT=0

for REL_PATH in "${TRACKED_FILES[@]}"; do
  FULL_PATH="${HOME}/${REL_PATH}"
  [ ! -f "$FULL_PATH" ] && continue

  CURRENT_CHECKSUM=$(sha256sum "$FULL_PATH" | cut -d' ' -f1)

  # Fetch latest baseline checksum for this boss + file from CK
  BASELINE=$(curl -s "${CK_URL}" \
    --data-urlencode "query=
      SELECT checksum_sha256
      FROM infra.config_baselines
      WHERE boss_id = '${BOSS_ID}'
        AND file_path = '${REL_PATH}'
      ORDER BY check_time DESC
      LIMIT 1
    " 2>/dev/null | tr -d '\n' | grep -oP '\w{64}' || echo "")

  if [ -z "$BASELINE" ]; then
    echo "[WARN] ${REL_PATH}: no baseline found — run 'kyb config snapshot' first"
    continue
  fi

  if [ "$CURRENT_CHECKSUM" != "$BASELINE" ]; then
    DRIFT_COUNT=$((DRIFT_COUNT + 1))

    # Determine file metadata for the drift event
    FILE_SIZE=$(stat -c%s "$FULL_PATH" 2>/dev/null || echo 0)
    FILE_MODE=$(stat -c%a "$FULL_PATH" 2>/dev/null || echo "644")
    GIT_STATUS="unknown"
    if git -C "${HOME}/.kyb" status --porcelain "${REL_PATH#.kyb/}" >/dev/null 2>&1; then
      if git -C "${HOME}/.kyb" diff --quiet "${REL_PATH#.kyb/}" 2>/dev/null; then
        GIT_STATUS="committed"
      else
        GIT_STATUS="uncommitted"
      fi
    fi

    # Who might have caused this? Check last logind or docker exec
    SUSPECT="unknown"
    LAST_USER=$(last -n 1 2>/dev/null | awk '{print $1}' | grep -v "^$" | head -1 || echo "unknown")
    LAST_DOCKER_EXEC=$(journalctl -u docker --since "24 hours ago" 2>/dev/null \
      | grep "POST /v.*/containers/.*/exec" | tail -1 \
      | grep -oP '(?<=POST /v[^/]+/containers/[^/]+/exec).*' || echo "")
    if [ -n "$LAST_DOCKER_EXEC" ]; then
      SUSPECT="docker-exec"
    elif [ "$LAST_USER" != "unknown" ] && [ "$LAST_USER" != "$BOSS_ID" ]; then
      SUSPECT="${LAST_USER}"
    fi

    echo "[DRIFT] ${REL_PATH}:"
    echo "        baseline: ${BASELINE}"
    echo "        current:  ${CURRENT_CHECKSUM}"
    echo "        suspect:  ${SUSPECT}"
    echo "        git:      ${GIT_STATUS}"

    # Compute diff if possible (for committed files)
    DIFF_PREVIEW=""
    if [ "$GIT_STATUS" = "uncommitted" ]; then
      DIFF_PREVIEW=$(git -C "${HOME}/.kyb" diff "${REL_PATH#.kyb/}" 2>/dev/null | head -20)
    fi

    # Log drift event to ClickHouse
    SAFE_REL_PATH=$(echo "$REL_PATH" | sed "s/'/\\\\'/g")
    SAFE_DIFF=$(echo "$DIFF_PREVIEW" | python3 -c "
import sys, json
print(json.dumps(sys.stdin.read())[:2000])
" 2>/dev/null || echo "''")

    curl -s -X POST "${CK_URL}" \
      -d "INSERT INTO infra.config_drifts FORMAT JSONEachRow {
        'boss_id': '${BOSS_ID}',
        'cluster': '${CLUSTER}',
        'detect_time': '$(date -u +%Y-%m-%dT%H:%M:%SZ)',
        'file_path': '${SAFE_REL_PATH}',
        'baseline_checksum': '${BASELINE}',
        'current_checksum': '${CURRENT_CHECKSUM}',
        'file_size': ${FILE_SIZE},
        'file_mode': '${FILE_MODE}',
        'git_status': '${GIT_STATUS}',
        'suspect': '${SUSPECT}',
        'diff_preview': ${SAFE_DIFF}
      }" --max-time 5 || echo "[WARN] Failed to log drift event"
  fi
done

echo "=== Drift check complete: ${DRIFT_COUNT} drifts found ==="

# Exit with code = drift count (useful for patrol integration)
exit $DRIFT_COUNT
```

### 5.2 Patrol Integration

The 5-minute patrol already checks container health and disk. Adding config drift detection:

```bash
# In patrol script, after container check:
# === Config Drift Check ===
if /usr/local/bin/kyb-config-check.sh; then
  echo "[PATROL] Config drift check: clean"
else
  DRIFT_COUNT=$?
  echo "[PATROL] Config drift check: ${DRIFT_COUNT} drifts found"
  # Log to patrol diary
  echo "[DRIFT] ${DRIFT_COUNT} config file(s) drifted" \
    >> "${DIARY_DIR}/$(date +%F)-infra-boss-night.md"
fi
```

### 5.3 Docker Event Trigger

When a container is restarted or created, the Docker event watcher triggers an ad-hoc config check:

```bash
# In docker-event-watcher.sh, after processing a restart/create event:
if [[ "$container_name" == kyb-infra-* ]] || [[ "$container_name" == kyb-registry-* ]]; then
  # Config may have changed during the restart — run a drift check
  (/usr/local/bin/kyb-config-check.sh &>/dev/null &)
fi
```

This catches drifts that happen during container lifecycle events (e.g., someone edited a config and restarted to apply, but forgot to snapshot).

### 5.4 ClickHouse Schema

```sql
-- ============================================
-- Table 1: Config Baselines (authoritative snapshot)
-- Stores the last-known-good checksums per boss per file
-- ============================================
CREATE TABLE infra.config_baselines (
    -- Identity
    boss_id         LowCardinality(String),       -- hostname of the boss container
    cluster         LowCardinality(String),       -- mac-orbstack | aliyun | office

    -- Snapshot metadata
    snapshot_id     String,                       -- 20260523T120000Z-infra-boss
    check_time      DateTime64(3),                -- when this baseline was recorded

    -- File identity
    file_path       String,                       -- relative to HOME: .config/kyb/config.yml
    checksum_sha256 String,                       -- SHA256 hex (64 chars)
    file_size       UInt32,                       -- size in bytes at snapshot time
    file_mode       String,                       -- permission octal: 644, 755, etc.

    -- Git status at snapshot time (informational)
    git_status      LowCardinality(String),       -- 'committed' | 'uncommitted' | 'not_a_repo' | 'unknown'

    -- Ingestion metadata
    _ingested_at    DateTime DEFAULT now()
) ENGINE = ReplacingMergeTree(_ingested_at)
ORDER BY (boss_id, file_path, check_time);

-- ============================================
-- Table 2: Config Drifts (detected anomalies)
-- Append-only log of every drift event
-- ============================================
CREATE TABLE infra.config_drifts (
    -- Identity
    boss_id         LowCardinality(String),
    cluster         LowCardinality(String),
    detect_time     DateTime64(3),                -- when drift was detected

    -- What drifted
    file_path       String,
    baseline_checksum  String,                    -- what it SHOULD be
    current_checksum   String,                    -- what it IS

    -- File metadata at detection time
    file_size       UInt32,
    file_mode       String,

    -- Context
    git_status      LowCardinality(String),       -- was the file committed at detection time?
    suspect         String,                       -- 'unknown' | 'docker-exec' | 'root' | username
    diff_preview    String DEFAULT '',            -- first 2000 chars of git diff (if applicable)

    -- Resolution
    resolved_at     Nullable(DateTime64(3)),      -- when drift was resolved
    resolution      LowCardinality(String) DEFAULT '',  -- 'snapshot_updated' | 'auto_reverted' | 'manual_restore' | 'acknowledged'
    resolution_note String DEFAULT '',

    -- Aggregation
    drift_duration_seconds Nullable(Int32),       -- resolved_at - detect_time

    _ingested_at    DateTime DEFAULT now()
) ENGINE = MergeTree
ORDER BY (detect_time, boss_id, file_path)
TTL detect_time + INTERVAL 365 DAY;

-- ============================================
-- Table 3: Config Snapshots (full-state snapshots)
-- Periodic full dumps of all tracked files (for forensics)
-- ============================================
CREATE TABLE infra.config_snapshots (
    boss_id         LowCardinality(String),
    cluster         LowCardinality(String),
    snapshot_id     String,
    snapshot_time   DateTime64(3),
    file_count      UInt8,                        -- how many files were tracked
    snapshot_json   String,                       -- full JSON payload of all checksums

    _ingested_at    DateTime DEFAULT now()
) ENGINE = MergeTree
ORDER BY (snapshot_time, boss_id)
TTL snapshot_time + INTERVAL 365 DAY;
```

### 5.5 Drift Severity Classification

Not all drift is equal. The severity depends on which file drifted, by how much, and the context:

| Drift | Severity | Condition | Action |
|-------|----------|-----------|--------|
| **config.yml changed** | P2 | Checksum differs from baseline | Notify, investigate — proxy/registry config affects all builds |
| **entrypoint.sh changed** | P2 | Checksum differs; git says uncommitted | Auto-revert if not committed within 5 min |
| **bin/kyb changed** | P2 | Checksum differs | Alert — CLI tool changes affect all sandboxes |
| **lib/*.rb changed** | P2 | Checksum differs; uncommitted | Alert — runtime behavior change |
| **Dockerfile changed** | P2 | Checksum differs from committed HEAD | Alert — next build uses different image |
| Generated file stale | P3 | `CLAUDE.md` doesn't match entrypoint.sh template | Re-generate, no alert (auto-heal) |
| Permission change | P4 | File exists but permissions changed | Log only (silent auto-heal) |
| File missing | P3 | Tracked file not found | Alert — may indicate corruption or partial deploy |

Combined threshold: **3+ P2 drifts on same boss in 24h** = P1 escalation (possible compromise).

## 6. Alert Rules

### 6.1 Immediate Alerts (Drift Fires)

| Rule | Condition | Severity | Channel |
|------|-----------|----------|---------|
| **ConfigFileDrifted** | New row in `infra.config_drifts` with P2 file | P2 | Feishu: "Config drift on ${cluster}/${boss}: ${file} changed (suspect: ${suspect})" |
| **ConfigMassDrift** | 3+ files drifted on same boss in same patrol cycle | P1 | Feishu: "Mass config drift on ${cluster}/${boss}: ${count} files changed — possible compromise?" |
| **ConfigDriftAutoResolved** | Drift resolved (file reverted to baseline) | Info | Feishu: "Config drift auto-resolved on ${cluster}/${boss}: ${file}" |
| **NoBaseline** | Boss has no baseline snapshot for > 1h after start | P3 | Feishu: "No config baseline for ${cluster}/${boss} — run 'kyb config snapshot'" |

### 6.2 Trend-Based Alerts (Accumulated Drift)

| Rule | Condition | Severity | Query |
|------|-----------|----------|-------|
| **RepeatOffender** | Same file drifted 3+ times in 7 days | P3 | `SELECT file_path, count() FROM infra.config_drifts WHERE detect_time > now() - 7d GROUP BY file_path HAVING count() >= 3` |
| **MultipleSuspects** | Same file drifted on 2+ clusters in 24h | P2 | Cross-cluster drift == deploy inconsistency |
| **LongLivedDrift** | Drift unresolved for > 24h | P2 | `SELECT * FROM infra.config_drifts WHERE resolved_at IS NULL AND detect_time < now() - 24h` |
| **DriftSpike** | > 5 drifts in 1h (unusual cluster-wide) | P2 | `SELECT count() FROM infra.config_drifts WHERE detect_time > now() - 1h` |

### 6.3 Patrol-Integrated Alert (Drift in Diary)

The 5-minute patrol already writes a daily diary. If config drift is detected, add:

```markdown
## Config Drift Report (2026-05-23 12:00 UTC)

| File | Cluster | Suspect | Since |
|------|---------|---------|-------|
| `.config/kyb/config.yml` | aliyun | docker-exec | 2026-05-23T10:15:00Z |
| `.kyb/entrypoint.sh` | mac-orbstack | uncommitted | 2026-05-23T11:30:00Z |
```

The diary entry is also a ClickHouse write, so dashboards can query it.

## 7. Remediation Strategies

### 7.1 Auto-Revert (For Low-Risk Drift)

For files that are pure git-managed source (not generated, not per-boss config), auto-revert is safe:

```bash
# In the detection script, for 'exact_match' files that are git-committed:
# Auto-revert if the file is in a git repo and has uncommitted changes
if [ "$GIT_STATUS" = "uncommitted" ] && [ "$AUTO_REVERT" = "true" ]; then
  echo "[AUTO-REVERT] ${REL_PATH} → git checkout HEAD"
  git -C "${HOME}/.kyb" checkout -- "${REL_PATH#.kyb/}"
  # Log the auto-revert as a drift resolution
  curl -s -X POST "${CK_URL}" \
    -d "INSERT INTO infra.config_drifts ... (resolution='auto_reverted')"
fi
```

**What gets auto-reverted:**

| File | Auto-revert safe? | Reasoning |
|------|-------------------|-----------|
| `entrypoint.sh` | Yes | Any legitimate change comes via git push |
| `bin/kyb` | Yes | Git-managed |
| `lib/*.rb` | Yes | Git-managed |
| `Dockerfile` | Yes | Git-managed |
| `mise.config.toml` | Yes | Git-managed |
| `config.yml` | **No** | Per-boss config, different per cluster |
| `clusters.yml` | **No** | Per-boss config |

### 7.2 Manual Acknowledgment (For P2+ Drift)

For per-boss configs that legitimately need different values per cluster:

```bash
# Acknowledge drift (mark as intentional)
kyb config acknowledge \
  --file .config/kyb/config.yml \
  --reason "Updated ACR registry_mirror for Aliyun region"

# This inserts a resolution row:
#   resolved_at = now()
#   resolution = 'acknowledged'
#   resolution_note = 'Updated ACR registry_mirror for Aliyun region'

# Then run snapshot to set new baseline:
kyb config snapshot
```

### 7.3 Snapshot Rollback

If a baseline was incorrectly updated (e.g., after a bad deploy), rollback to a previous snapshot:

```sql
-- Find the last known-good snapshot (before the bad deploy)
SELECT snapshot_id, check_time
FROM infra.config_baselines
WHERE boss_id = 'infra-boss'
  AND file_path = '.config/kyb/config.yml'
ORDER BY check_time DESC
LIMIT 5;

-- Restore: manually copy the baseline checksum from the desired row
-- and re-apply to the container, then snapshot again.

-- To restore a previous baseline as the current one:
INSERT INTO infra.config_baselines (boss_id, cluster, snapshot_id, check_time, file_path, checksum_sha256, ...)
-- Copy values from the historical snapshot you want to restore
```

### 7.4 Drift Escalation Path

```
drift detected
    │
    ├── P4 (permission/info) → log only → auto-heal on next patrol
    │
    ├── P3 (missing file, generated file stale) → log + diary
    │   └── if unresolved for 24h → escalate to P2
    │
    ├── P2 (config change, uncommitted source change)
    │   ├── auto-revert (if safe + source-managed) → log resolution
    │   └── manual (if per-boss config or auto-revert fails)
    │       ├── acknowledged → snapshot required
    │       └── unattended for 24h → escalate to P1
    │
    └── P1 (mass drift, suspected compromise)
        ├── immediate Feishu alert
        ├── diary entry
        └── human must investigate
```

## 10. Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| **False positives from legitimate deploys** | High | Medium | Snapshot runs after every deploy, so baseline is always current. Drift means "different from last deploy." |
| **Script not running (missed patrol)** | Low | Medium | Patrol runs every 5 min; if config-check.sh fails, patrol continues but logs warning. Next patrol retries. |
| **ClickHouse unreachable during drift check** | Low | Low | Drift check degrades gracefully: if CK is down, log to local file and retry next patrol. No double-reporting. |
| **Auto-revert overwrites legitimate uncommitted change** | Low | High | Auto-revert only applies to git-managed files with committed changes. Per-boss configs (config.yml) never auto-revert. |
| **Snapshot too large for CK** | Low | Low | Each snapshot is < 2 KB JSON. Even at 1 snapshot/min/boss, volume is ~8 MB/day for 3 bosses. Trivial. |
| **Operator edits config, forgets to snapshot** | Medium | Medium | Next patrol detects drift and alerts. Operator then acknowledges and snapshots. If no ack within 24h, escalate. |
| **Checksum collision** | Negligible | High | SHA256 collision risk is astronomically low (< 1 in 10^77 for 2 files). Not a practical concern. |
