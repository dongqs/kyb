## 今日进展（2026-05-24 下午）

### 飞书 bot 全面替换（MR #153 ✅）

**问题：** lark-claude-bridge → watcher → claude --print 链路过长，空响应频繁；lark-cli 未安装；cc-connect 双重回复。

**新架构（四层）：** Chat（飞书收发）→ Runtime（调度）→ Agent（执行）→ Heartbeat（心跳）

| 项目 | 说明 |
|------|------|
| 新 bot | `bin/feishu-bot` + `lib/kyb/feishu_bot.rb`，直接调飞书 API |
| 全消息检测 | 所有消息都通知，不限于 @ |
| 三档心跳 | 1m 快检 / 10m 中检 / 30m 详检 + 轮播提示 |
| CK 日志 | message_mention / message_new / heartbeat 全量入库 |
| 防注入 | 外部消息内容不入会话，仅固定通知 |
| 错误处理 | 指数退避、限流（30s/5msg）、已读去重 |
| 测试 | 28 Ruby 单元 + 7 shell 集成，全部 CI ✅ |
| 回复命令 | `bin/feishu-reply` |

**旧链路停用与根因：**
- **infra-cc-connect 容器**（已 stop）— 这才是之前空响应的真凶，独立 Claude 进程自动回复
- **infra-boss tmux session**（已 kill）— lark-claude-bridge 的 watcher
- 两个旧链路互不依赖，导致双重回复

**三方 review 修复：**
| 方向 | 发现 | 修复 |
|------|------|------|
| 网络/安全 | SOCKS5 无效、SQL 注入 | gsub 块形式修注入，SOCKS5 不阻塞 |
| Ruby/架构 | 死代码、常量位置 | with_retry 清理、KNOWN_USERS 移顶部 |
| Shell/运维 | CK 静默失败、TSV 假阳性 | ck_ensure()、TabSeparated、file 检查 |
