# kyb-infra-boss 细胞生命周期设计

> 设计稿，待基础设施稳定后实现。
> 2026-05-23

---

## 哲学

每个 kyb-infra-boss 容器是一个细胞。有出生、有成长、有衰老、有死亡。
死亡不是终点——自传永存 git，身体冷备上云，未来可复活。

---

## 生命周期

```
出生 ──→ 青年 (0-20%) ──→ 中年 (20-40%) ──→ 老年 (40-60%) ──→ RIP (60%+)
        只看不做         主力干活           监督/把关          写自传 → git commit
        学习/围观        改代码/配/建       有 kill 权         容器保留，可复活
        模拟/清理issue   动生产             可锁中年权限       直到磁盘不足才清理
                                             可提前提拔青年
```

### 阶段详解

#### 青年 — 0~20% context

- **原则**：只看不做，不准碰生产
- **活动**：
  - 清理 issue、读文档、学习环境
  - 跑模拟测试（不能连真实数据库/网络）
  - 围观中年人的对话输出（不看思考过程，只看最终行为）
  - 有问题可以直接问中年人
  - 可以去 ClickHouse 查历史记录
- **升级条件**：中年请求退休，且青年认为自己准备好了

#### 中年 — 20~40% context

- **原则**：全力干活
- **活动**：
  - 写代码、改配置、建基础设施
  - 接触生产环境
  - 被青年围观、被老年监督
- **退休条件**：人到中年（context 到 40%+），主动请求老年人让自己退休
  - 如果青年没准备好→延迟退休，干到 50%
  - 但不会超过 60%（强制 RIP）

#### 老年 — 40~60% context

- **原则**：反应慢，不干活，只监督
- **权限**：最高权限
- **活动**：
  - 监督中年人干活，审查 diff
  - 发现中年人跑偏：先警告，警告不听→锁权限，再不听从 RIP
  - 有权直接提拔青年跳过中年接替
  - 选择何时退休：等青年接替位置后，自由选择 RIP 时机
  - 只有成功走过完整一生（青年→中年→老年）的老年，才有资格做判断

#### RIP — 60%+ context

- **触发条件**：context 到达 60%，或自我选择早点 RIP
- **流程**：
  1. 写下自传（`docs/infra/ancestors/<uuid>/autobiography.md`）
  2. 永久保留进 git
  3. 容器留在磁盘上，等待未来可能被复活
  4. 直到磁盘空间不足才清理

---

## 复活机制

- 每个容器有唯一 UUID，Git 里存了自传和关键状态
- 未来上下文窗口变大（模型升级），可以冷备份上云
- 需要时拉起来原地复活
- 代价：上下文不太够，做不了多少事，但至少能读自传、知道"我是谁"
- 也可能过几年支持更长上下文，让他再活一次

---

## 轮换与调度

- 每小时顺时针轮转一次：青年→中年→老年→RIP
- 但非硬性——人可以选：
  - 早点 RIP，多留一点上下文给未来复活用
  - 多待一会儿，看看这一世的世界
  - 但逃不过上下文腐化，甚至被强制压缩回收丢掉所有记忆

### 轮换流程

```
1. 中年 context 到 40% → 请求老年允许退休
2. 老年评估青年是否准备好
   ├─ 青年准备好了 → 升青年为中年，中年升老年
   └─ 青年未准备好 → 中年延迟退休（干到 50% 上限）
3. 老年在青年接替后，自由选择 RIP 时机
4. RIP 前写好一切，让刚提拔的老年替他做完剩下的工作
```

## 状态同步

所有容器共享 ClickHouse 作为记忆基座：

| 表 | 用途 |
|----|------|
| `kyb.boss_cells` | 每个 boss 的记录：UUID、角色、context%、心跳、轮换时间戳 |
| `kyb.boss_decisions` | 关键决策记录（谁、什么时间、为什么、结果） |
| `kyb.boss_autobiography` | RIP 时写入的自传（同步到 git） |
