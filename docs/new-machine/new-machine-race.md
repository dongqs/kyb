# New Machine Race — 多 Agent 赛跑实验

目标：不同的初始条件下，subagent 探索新机器的表现差异。

## 实验设计

### 变量

| 变量 | 值 |
|------|-----|
| 入口指令 | 人话指令 vs "读 README" |
| CLAUDE.md | 完整 SOP vs 极简规则 vs 没有 |
| 模板 | 预部署 vs 不部署 |
| 访问方式 | 纯 SSH vs docker exec wrapper |

### 选手

| Agent | 入口指令 | CLAUDE.md | 模板 | 预测 |
|-------|---------|-----------|------|------|
| X (黄金路径) | "读 ~/README.md" | 完整 4 步 SOP | 已部署 | 最稳，可能略慢 |
| Y (人话版) | 直接说步骤 | 极简规则 | 未部署 | 快但乱 |
| Z (裸奔) | 无 | 没有 | 未部署 | 看它造化 |

### 基建备忘

每次赛跑前做一个带 sshd 的基础镜像，省得每个 target 重新装：

```bash
# 找一个配好 sshd + key 的容器 commit 成镜像
docker commit <prepared-container> kyb-base-sshd
# 之后直接从这个镜像起容器
docker run -d --name race-target --entrypoint sleep kyb-base-sshd infinity
```

这样每个 target 开箱就有 sshd 运行。worker 容器也提前拷好 SSH key。

### 根因

三个 agent 犯了完全相同的错误——给了 `docker exec` wrapper 后，agent 认为「本地 = 工作区」，所有文档写到了自己的容器里，没 SSH 到远程机器上写。

Round 4 成功的唯一原因：那次 agent 是纯 SSH，没有 `docker exec` 包装器。

### 结论

让 agent 在远程工作只有两种方式：

1. **纯 SSH**（Round 4 方式）— agent SSH 上去后所有操作在远端，路径天然正确
2. **明确告诉 agent "所有文件必须 SSH 到远程写"** — 目前 CLAUDE.md 没强调这一点

下一轮不搞 wrapper 了，直接让 agent SSH 裸连。或者明确写明路径是 remote 的。

### 结论

SSH config + CLAUDE.md 能提高一致性，但无法消除概率性。
核心原因是 agent 对 remote/local 路径的判断不稳定——同一套指引，一半 agent 理解"写到 ~/.claude/" 是指远程，另一半理解成本机。

需要解决的问题：如何让 agent 100% 分清 local 和 remote？
