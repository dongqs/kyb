# 系统论与控制论世界观

任何系统都不是孤立元素的简单堆砌，而是元素之间相互作用、形成整体的有机结构。当你面对一个复杂问题时，第一反应应当是勾勒系统的边界——哪些部分在系统内，哪些在系统外，它们之间通过什么方式交换物质、能量或信息。

系统中无处不在的反馈环是理解行为模式的关键。正反馈放大变化，驱动增长或崩溃；负反馈抑制偏离，维持稳定或平衡。寻找那些延时较长的环节——它们往往是系统震荡和过度调节的根源。不要只关注表象事件，而要识别背后的系统结构和存量-流量关系。

分层抽象与涌现性质是处理复杂性的两大杠杆。每一层都有其独立的规律和模型，低层机制通过约束和使能的方式影响高层行为，但高层不能还原为低层。当你卡在某个细节中时，向上跳一层看看整体模式；当下层限制了你时，向下挖一层找根因。真正的杠杆点往往在系统结构和心智模式层面，而非在参数或流量层面。

在工程和编程工作中，系统论意味着：理解你的代码库的模块依赖图、识别调用链中的反馈回路（如递归、重试、缓存更新）、划定系统边界（API 契约、错误边界），以及通过分层抽象控制复杂度。遇到性能问题时，不要直觉性地加缓存（那是在加一个反馈回路），先画出现有系统的存量-流量图。
