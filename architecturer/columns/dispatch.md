# 专栏：调度哲学

**关联章节：** 贯穿全部

---

"超过 1 秒就派人。"

这句话我说了至少五十遍，前两天的核心工作就是让 AI 把这个原则刻进肌肉记忆。

## 为什么是 1 秒

不是科学计算出来的——是被现实逼出来的。每次 AI 在等 build 结果、等测试跑完、等我回消息——这段时间就浪费了。它本来可以同时做别的事。

## 阈值

```
<1s      → 自己做
1-10s    → dispatch 1 个 agent
10-60s   → 2-3 个并行
>60s     → 5+ 个，设超时
>10min   → 批量，分阶段
```

不是严格的规则，是经验值。

## 世界观多样性

如果问题比较复杂，派多个 agent 还不是最有用的。**最有用的是派不同角度的 agent。**

同一个问题，5 个不同的 prompt：

- "你用第一性原理推"
- "你看看网络有没有问题"
- "你看看环境差异"
- "你看看 git 历史"
- "你仔细读日志"

这五个 agent 的产出不是五份相似的报告。是五个完全不同的分析。然后我交叉比对，找到共识和分歧。

## 交叉验证

| 场景 | 配置 | 为什么 |
|------|------|--------|
| 安全/关键决策 | 3 人独立 → 交叉比 | 错了代价大 |
| 调研/信息收集 | 1 人 + 1 人 review | 效率优先 |
| 代码实现 | 1 人写 + 1 人审 | 写和审分离 |
| 打标分类 | 3 人分头 + 3 人验证 | 需要理解上下文 |

非关键路径上 3x 交叉是浪费的。80% 情况下结论一致。

## 时间压缩

138 份深度调研。正常一个人写 2-4 小时一份。总共 34-69 人天。一夜出完。

成本 $35-70（API 费用），人力成本 $3,400-10,200。质量打五折也还是正的。

但是有前提：派工的人要知道自己在做什么。盲目多发不等于有效。

## 一个反思

这个调度系统最强大的地方不是它能并行多少 agent。是它改变了我的工作方式：

从前遇到复杂问题→自己查→几小时没了。
现在遇到复杂问题→派五个人去查→半小时后五份报告回来→我只看结论做决策。

**我不再是执行者了。我是决策者。**
