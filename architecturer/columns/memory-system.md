# 专栏：记忆系统为什么分四层

**关联章节：** [第二章](02-growing-pains.md)

---

AI 只有 5 秒记忆。这不是比喻，是真的——上下文窗口一满，前面聊了什么就忘了。

这个问题困扰了我很久。后来想明白的是：**不要试图用一种技术解决所有时间尺度的问题。**

## 四层设计

我分了四层，每层解决不同的问题：

| 层 | 持久度 | 技术 | 解决什么问题 |
|----|--------|------|-------------|
| 金鱼脑子 | 5 秒 | 上下文窗口 | 当前对话。容量有限，用完即忘 |
| Memory | 3 小时 | 文件系统 | 当前 session。修一个 bug 的过程中间被打断，回来还能接上 |
| ClickHouse | 30 天 | 数据库 | 跨 session。"上周那个项目怎么配的来着" |
| 文档 | 永久 | git | 跨代传递。下个人来的时候不用重头踩坑 |

## 为什么这么分

一开始只有金鱼脑子 + Memory。够用，但有两个问题：

问题一：**换 session 就丢。** 上午查了一个问题的根因，下午开新 session 又要重新查。Memory 文件不清就不会丢，但 AI 不太会主动读。

问题二：**查不到历史。** "前天那次 CI 挂是因为什么？"——没人记得。CK 解决了这个问题。所有 agent 事件都往 CK 写，什么时候想查就查。

但 CK 也有保留期，30 天滚动。重要的事情还是要写成文档。

所以第四层是最重要的，也是最难坚持的。写代码比写文档爽太多了。我说"每次不想写文档的时候就拿出来念一遍"，是真的在念。

## 一条线串起来

> "我们都是金鱼脑子只能记5秒 memory能记3小时 ck让我们能记30天 文档可以传给下一代。"

这句话是我说的。它是整个系统的核心哲学。
