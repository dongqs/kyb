# 第六章：善后 — 把波动源全杀了

**2026-05-24 | Day 4**

---

前三天蹦了一整夜的迪。第四天扫地。

做了一件事：**找到那些反复出现的问题，把根因挖出来消灭。**

## 杀了四个波动源

四个问题，每个都不是大故障，但每个都反复出现。每次出现都要花 20-30 分钟排查和修复。

### 1. nuc8 隧道

**症状：** git.leyantech.com 突然就不可达了。查一圈发现 nuc8-proxy 路由到了死 IP。

**根因：** SSH 隧道。容器重建后隧道消失。以前重建后要手动 ssh 重新建。

**修复：** 改 `entrypoint.sh`——infra-boss 启动时自动安装 autossh、建隧道、断线重连。以后不管怎么重建，活着就有隧道。

### 2. sing-box 端口映射

**症状：** 宿主机上 `127.0.0.1:2080` 没人监听了。所有走代理的请求断掉。

**根因：** 重建 sing-box 容器时忘了加 `-p 2080:2080`。

**修复：** 记到文档里，下次重建时抄参数。还有更好的办法——用 docker-compose 或 stack 定义，但我还没做到那一步。

### 3. sing-box 容器网络

**症状：** 重建后 sing-box 跟其他容器不在一个网段。容器名 DNS 不通。

**根因：** 重建时没指定 `--network`，落到了默认 bridge。

**修复：** 重建时明确加 `--network kyb-net`。

### 4. sing-box 配置指向死 IP

**症状：** nuc8-proxy server 配置写着 `192.168.97.17`——不存在的 IP。

**根因：** `sb-config-v2` volume 里的配置是写死的。容器重建后 .17 这个 IP 可能变了。

**修复：** 从宿主机只读 mount 读配置，改完之后写回 volume。这样下次改配置改宿主机文件就行，不用进容器。

## 稳定交接

修完之后写了交接清单。目标是：**以后回来的人不用再踩一遍我们踩过的坑。**

```bash
# 5 条命令确认系统健康
docker ps --filter name=kyb-infra               # 容器都在
curl -x socks5://127.0.0.1:2080 -sI https://github.com  # 外网代理通
curl -x socks5://127.0.0.1:2080 -sI https://git.leyantech.com  # 内网隧道通
docker exec kyb-infra-boss ss -tlnp | grep 2081  # 隧道在监听
df -h /                                          # 磁盘够
```

## 还有四个没修

我也诚实地记下了还烂着的东西：

1. `entrypoint.sh` 没有自动修 sing-box 配置的逻辑（如果下次重建后 IP 又变了，还得手动）
2. 所有容器缺 `NO_PROXY`——全部流量走代理，有性能损失
3. 所有容器缺 `--init`——已知红牌，还没动
4. 所有容器无内存限制——同上

特别是 `--init` 和内存限制，我知道必须做。只是第四天实在没力气了。
