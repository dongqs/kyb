# 组织原则

## 控制论先于系统论

> 先关掉反馈回路，再搭上层架构。

不是选择——是被现实逼出来的。

- 测试坏了 → 先修 → 再优化测试框架
- CI 红了 → 先修 → 再看 CI 架构
- rm cname bug → 先修 → 再想统一设计

## 先反馈再架构

kyb 的演化顺序不是自上而下的设计，而是自下而上的涌现：

1. **反馈层**（Day 1-2）：修测试、修 CI、修 bug——让系统能自我修正
2. **可观测层**（Night 1）：Grafana、CK events、metrics——让系统能看见自己
3. **架构层**（Day 3-4）：消灭波动源、文档化——让系统能持久

每一层都依赖上一层稳定。反馈坏了，观测就是盲的。观测盲了，架构就是空中楼阁。

## 飞轮效应

```
反馈稳定 → 看见系统 → 做出决策 → 架构改进 → 更稳定的反馈
```

每一轮 iteration 让下一轮的循环加速度更快。
