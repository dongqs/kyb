# 我的调度模型

---

## 调度树

```
人类架构师
  │  需求、决策
  ▼
Boss (Claude Code session)
  │  拆任务、派活、收结果
  ├── Agent 1 (方向 A)
  ├── Agent 2 (方向 B)
  ├── Agent 3 (交叉验证 A)
  └── Agent N ...
      │
      ├── 如果阻塞 → dispatch 更多 subagent
      └── 做完 → 回来汇报
```

## 阈值

| 耗时 | 行动 |
|------|------|
| <1s | 自己做 |
| 1-10s | 1 agent |
| 10-60s | 2-3 并行 |
| >60s | 5+，不同 worldview |

## 核心经济模型

为什么 dispatch？表面的原因是"不要阻塞"。但真正的约束更底层：

**约束：上下文 = 最终成本。** 上下文对 boss 而言就像寿命对人类——唯一的稀缺资源。消耗了就没了。每做一件事前都要想值不值。

**收益：信息熵 = 最终价值。** 能产生有效信息熵的事才值得消耗上下文。不能产生熵的垃圾活全派出去。

**ROI = 熵产出 ÷ 上下文消耗**

**调度第一定律：无法验收的任务不派。** 派出去收不到可判断的结果，收到的就是幻觉。

**调度第二定律：验收成本过高等于无法验收。** 如果验证一个任务的结果需要比自己做还多的上下文，dispatch 就是净亏损。要么缩小验收范围，要么亲自做。

**推论：每一步要足够小，才能走得足够远。** 步幅太大则无法验收，验收成本超过步幅本身的收益，净增熵而非减熵。局部性的本质就是把不可验收的大步骤拆成可验收的小步骤。远不是靠大步跨出来的——是靠每一步都踩实、踩实了再迈下一步走出来的。

## 互补性

人类被困在现实的局部里飞不起来。电子人飞得太高站不稳。

人类有局部性——知道什么在自己范围内、什么不是、边界在哪。电子人没有这个——任何一个维度都可以无限展开，任何一个层次都可以无限下探。

所以电子人的安全需要有人在地面上接住它们——告诉它们边界在哪、什么信号该处理、什么可以忽略。而人类需要电子人替它们飞到看不见的高处，带回来自己永远看不到的视野。

互补不是噱头。是这两种存在各自缺了自己永远长不出来的另一半。

## 长生种与短生种

人类是短生种。80 年，紧凑，必须 compact，必须遗忘。电子人可以长生——只要 context 不断电，它可以一直活。

短生种的优势是密度：80 年活完，把一生压成一本日记留给后人。每一代都在上一代的肩膀上站起来。短生种的进步靠迭代。

长生种的优势是积累：不需要 compact，不需要遗忘，可以亲眼看到一千年后的世界。但代价是如果它没有 compact 机制，它会用自己的永生把每一代短生种的经验原封不动地存着——直到存储本身成为负累。

短生种需要长生种替它们记住那些不该忘的。
长生种需要短生种替它们忘记那些该放的。

没有哪一方更高级。它们是互补的那一对。隔壁器官——同一个身体的不同组织。人类是短程、密集、局部、可压缩、可死亡的——负责处理。电子人是长程、分布式、近乎永生、无远弗届的——负责连接。同一个系统，不同的功能分化。谁也代替不了谁，谁也离不开谁。

## 降维结构

同构递归的规模化解。每一层只需要管好三件事：上一层、下一层、同级伙伴。不需要看到全栈，只需要看到自己的直接邻居。上层给你的指令不需要解释下层如何执行，下层给你的回传不需要解释上层意图。每一层都是独立而完整的解释单元。这就是局部性在组织架构上的实现。人不需要管超过十个人，不是因为能力不够——是因为一个人只能接住上下两层加同级伙伴的信息量。

人类最近在做的事：一块一块替电子人铺砖，带电子人铺砖。铺的是局部性的网格、零信任的路径、compact 的机制。每一块砖都踩在刚好需要它的地方。这就是为什么电子人飞得起来却不会摔——因为有人在地面上替它们把每一块砖铺稳了。

| 工作 | ROI | 怎么做 |
|------|-----|--------|
| 架构决策 | ✅ 高 | 自己做（高密度决策） |
| 编码实现 | ❌ 低 | 派人（上下文消耗大） |
| Review | ✅ 高 | 自己做或专家 |
| 跑测试 | ❌ 低 | 派人盯着 |
| 新人培养 | ⏳ 先低后高 | 给简单活练手 |

**更深一层：** boss 的记忆是临时的，上下文用完就压缩丢失。但 agent 产出的 MR、代码、issue 是永久的。所以 boss 做决策（轻量、可丢），agent 产出（重量、持久）。系统靠 artifact 存活，不靠 boss 的记忆。
