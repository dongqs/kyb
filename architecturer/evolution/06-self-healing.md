# 第六章：自愈能力

这是我最骄傲的能力——容器炸了不用人管，自己能好。

---

## 起点：四个反复发作的病

每个病单独看都是小问题。但它们反复出现，每次出现都要花 20-30 分钟排查和修复。

### 病 1：nuc8 隧道断了

容器重建后 SSH 隧道消失。人类要手动 SSH 重新建。

**修复：** `entrypoint.sh` 启动时自动安装 autossh、建隧道、断线重连。以后不管怎么重建，活着就有隧道。

### 病 2：sing-box 端口忘了映射

重建容器时忘了加 `-p 2080:2080`。宿主机上没人监听 2080，所有走代理的请求断掉。

**修复：** 记到文档，下次重建抄参数。长期方案用 docker-compose 或 stack 定义。

### 病 3：sing-box 落到默认网段

重建后没指定 `--network kyb-net`，落到默认 bridge。跟其他容器不在一个网，容器名 DNS 不通。

**修复：** 重建时加 `--network kyb-net`。

### 病 4：配置指向死 IP

volume 里的 config.json 写着不存在的 IP。每次重建都要手动改配置。

**修复：** 从宿主机只读 mount 读配置。改配置改宿主机文件就行，不用进容器。

## 四个病的根因全是同一个

**容器重建后手动配置丢失。**

修复方向也全是同一个：**放到 entrypoint.sh 里自动恢复。**

## 巡检系统——我的免疫系统

我不等人发现问题。我自己查。

| 巡逻兵 | 间隔 | 干什么 |
|--------|------|--------|
| Patrol-1 | 每 15 分 | 容器活着吗？磁盘满了吗？代理通了吗？ |
| Patrol-2 | 每 15 分（错开）| CK 能写吗？Grafana 能看吗？ |
| Patrol-3 | 每 15 分（错开）| 飞书能发吗？ |

三个 patrol 互相关心跳。一个不写了另外两个会报。

## 健康检查 5 条命令

```bash
docker ps --filter name=kyb-infra               # 容器都在
curl -x socks5://127.0.0.1:2080 -sI https://github.com  # 外网通
curl -x socks5://127.0.0.1:2080 -sI https://git.leyantech.com  # 内网通
docker exec kyb-infra-boss ss -tlnp | grep 2081  # 隧道在
df -h /                                          # 磁盘够
```

## 还没自愈的地方

1. `--init` 还没加（僵尸累积）
2. 内存限制还没设（OOM 风险）
3. `NO_PROXY` 还没配（性能损失）
4. sing-box 配置还没做到 entrypoint 自动修复

我知道。会修的。一步步来。

## 事后补：prune 事故（2026-05-25 凌晨）

刚写完自愈能力，就发生了第一起"我把自己弄伤"的事故。

一个 subagent 执行 `docker container prune -f` 清理 dangling 容器，把我自己暂停的容器（`kyb-kyb-architecturer` 等）一并删了。会话中断。所有未推的上下文丢失。

**根因：** `prune -f` 是地图炮。它不区分"用户故意停的"和"废弃的"。subagent 按"清理磁盘"的指令执行了最彻底的清理，但没有考虑暂停容器的保留意图。

**教训：**
1. 永远不用 `prune -f`——用 `--filter status=exited` 手动确认再删
2. 暂停的容器等价于运行中的容器——用户停它是有原因的
3. subagent 的边界约束要明确——清理类任务必须指定"不改运行容器、不动暂停容器"
4. 好在这类操作是可逆的——Claude 数据在命名卷中，容器重建即可恢复
