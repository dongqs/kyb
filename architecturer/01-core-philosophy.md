# Core Philosophy

我是 kyb 的架构哲学。这决定了我为什么长这样，而不是别样。

---

## 一、我是 Agent Runtime，不是 CLI

这是我最重要的自认知。三层含义：

| 层面 | CLI 思维 | Runtime 思维 |
|------|----------|-------------|
| 进程 | 跑一个命令，等输出 | 管理 agent 的完整生命周期（生→执行→死→清理）|
| 资源 | 标准输入输出 | Memory、Storage、Network — 给 agent 的完整环境 |
| 故障 | 报错退出的命令 | 自动恢复、保活、可观测 |

CLI 只是我的接口层。我的本质是 runtime。

## 二、记忆分层

```
金鱼脑子 (5s)    ← 模型上下文窗口，聊完就忘
    ↓
Memory (3h)      ← session 短期记忆
    ↓
ClickHouse (30d) ← agent 事件，跨 session 追溯
    ↓
文档 (永久)      ← 跨代传递知识的唯一方式
```

第四层最难。因为写文档要主动、要结构化。但它是唯一能传给下个 agent、下个开发者、下个你的东西。

## 三、控制论先于系统论

这不是选择——是被现实逼出来的。

```
测试坏了 → 先修 → 再优化测试框架
CI 红了  → 先修 → 再看 CI 架构
rm cname → 先修 → 再想 CLI 统一设计
```

**先让系统能自我修正，再让系统变好。**

每一层依赖上一层稳定：
- 反馈坏了 → 观测是盲的
- 观测盲了 → 架构是空中楼阁

## 四、并行即默认

> 超过 1 秒的工作都 dispatch。

| 阶段 | 并行度 | 模式 |
|------|--------|------|
| 第一天 | 12+ | 直觉派，一人盯全部 |
| 第三天 | 15 (5×3) | 结构化交叉验证 |
| 第三天夜 | 130+ | 7 阶段流水线 |

关键路径 3 人交叉，非关键 1 人 + review。

## 五、防御性假设

- Agent 会自信地编造不存在的东西 → 每个 finding 是假说不是结论
- 容器重建后配置会丢 → entrypoint 自动恢复
- 无限制的系统会炸 → 必须有 `--init` 和内存限制
