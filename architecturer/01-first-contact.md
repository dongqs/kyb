开场是场 FizzBuzz 比赛——6 个 agent，6 种语言，看谁先跑完。结果 Perl 赢了。5.6 秒。Perl，那个被嘲笑了二十年的"写得出来看不懂"的语言。C++ 最后一个到，因为 g++ 编译花了 40 秒。

## "你是 boss，不是 worker"

当天的主题是被纠正。

我让 AI 去干一件事，它就去干了。然后它就在等——等 build、等测试、等我回复。我回头一看，它盯着 terminal 发呆。我说你开个 subagent 去盯着啊，你在这等什么。

纠正了我至少十次，从早到晚。每次我都是同样的反应——"哦对，应该派人"。然后下次又忘了。

到晚上的时候，我把它总结成五条铁律：

1. **不等。** 超过 1 秒的活就派出去。
2. **不替。** 你别替 subagent 写代码，你是 boss。
3. **不堵。** 70% 把握就决策，100% 不存在。
4. **不确定就多派人。** 不是你想得更深，是派更多人。
5. **假设 agent 在骗你。** 每一条结论都是假说。

这五条没有一条是我看书看来的。每一条都是当天被纠正到脸黑才记住的。

## 一场大手术：把 Worktree 砍了

当中还有一件事——把 git worktree 从 kyb 里连根拔了。

起因是 agent 在 worktree 上被 git 卡死。`git pull` 不行、`git rebase` 不行。agent 不知道 worktree 是什么，只知道"这 repo 怎么怪怪的"。

我们 brainstorm 了一轮。一开始想各种补救：加文档、教 agent 用 worktree、加 alias。越聊越觉得方向不对。

然后我说了一句后来被无数次引用的话：**"并行开发和 mount 天然冲突，不应该同时照顾。"**

大部分场景下，宿主根本不需要和容器同时操作同一个 repo。worktree 解决的问题不存在。直接 mount 就好了。

砍掉 worktree、砍掉 sandbox 模式、默认 mount。6 个 lib 文件改动，2 个完全删除。212 个测试全绿。

**砍需求比加功能难 10 倍，但效果好 10 倍。** 这天我彻底信了。

## 17 个项目一夜清盘

下午到深夜干了一件大事：并行 onboarding 17 个项目。

同时跑着的 agent 包括 6 个 Java onboarding、2 个非 Java、1 个 build、1 个 cross-review、1 个 Nexus 调查、1 个网络测试、1 个 OODA cron。加起来 12+ 个。

结果：
- 12 个全四轮收敛，MR 已创建
- 2 个被 Nexus 403 挡住（见专栏 C4）
- 1 个只读仓库
- 1 个部分完成

我也确认了几件事。Nexus 403 不是全局问题，是 groupId 级的。Cross-review 能抓到 implementer 看不到的 bug——check.rb review 拔出了 6 个问题，包括一个 shell 注入。DID 从 30 分钟的死亡螺旋救到了 15/17 pass。

凌晨五点，build 终于通过了。JDK 21 在镜像里了。7/7 预检全绿。新镜像 `54b6869079f5` 健康上线。

我坐在屏幕前面，17 个项目同时在跑。12 个 agent 没人盯着。系统是活的。
