第六章：善后 — 把波动源全杀了

**2026-05-24 Day 4**

前三天蹦了一整夜的迪。第四天扫地。

做了一件事：找到那些反复出现的问题，把根因挖出来消灭。

杀了四个波动源

四个问题，每个都不是大故障，但每个都反复出现。每次出现都要花 20-30 分钟排查和修复。

1. nuc8 隧道

症状： git.leyantech.com 突然就不可达了。查一圈发现 nuc8-proxy 路由到了死 IP。

根因： SSH 隧道。容器重建后隧道消失。以前重建后要手动 ssh 重新建。

修复： 改 entrypoint.sh——infra-boss 启动时自动安装 autossh、建隧道、断线重连。以后不管怎么重建，活着就有隧道。

2. sing-box 端口映射

症状： 宿主机上 127.0.0.1:2080 没人监听了。所有走代理的请求断掉。

根因： 重建 sing-box 容器时忘了加 -p 2080:2080。

修复： 记到文档里，下次重建时抄参数。最好的办法是用 docker-compose 或 stack 定义，但我还没做到那一步。

3. sing-box 容器网络

症状： 重建后 sing-box 跟其他容器不在一个网段。容器名 DNS 不通。

根因： 重建时没指定 --network，落到了默认 bridge。

修复： 重建时明确加 --network kyb-net。

4. sing-box 配置指向死 IP

症状： nuc8-proxy server 配置写着 192.168.97.17——不存在的 IP。

根因： sb-config-v2 volume 里的配置是写死的。容器重建后 .17 这个 IP 可能变了。

修复： 从宿主机只读 mount 读配置，改完之后写回 volume。以后改配置改宿主机文件就行，不用进容器。

稳定交接

修完之后写了交接清单。目标是：以后回来的人不用再踩一遍我们踩过的坑。

bash # 5 条命令确认系统健康 docker ps --filter name=kyb-infra # 容器都在 curl -x socks5://127.0.0.1:2080 -sI https://github.com curl -x socks5://127.0.0.1:2080 -sI https://git.leyantech.com docker exec kyb-infra-boss ss -tlnp | grep 2081 df -h /

还有四个没修

我也诚实地记下了还烂着的东西：

  1. entrypoint.sh 没有自动修 sing-box 配置的逻辑
  2. 所有容器缺 NO_PROXY
  3. 所有容器缺 --init——已知红牌
  4. 所有容器无内存限制

特别是 --init 和内存限制，我知道必须做。只是第四天实在没力气了。

四天前，从一场 FizzBuzz 比赛开始。四天后，12 个容器全线稳定，130+ agent 并行验证过，记忆系统从 5 秒到永久分层，所有核心决策都有记录。

跟四天前比，最大的区别不是多写了多少代码。是系统再也不会因为容器重建就挂了。

而且下次再有人来，不会在同一个坑里摔倒了。
