# 2026-05-27 — 最小可测

## 卡点诊断

"我不知道什么地方卡住了我的上下文"

追踪后发现是**未收敛的等待决策**堆积。每件事都开一个线程挂着，攒多了就头疼。不是干不了活，是决策队列满了。

## 突破

**最小可测。** 四个字一说出来，人就松了。

回想之前的"爆炸"——那是系统检测到自己的架构有问题（试图一次性设计整个系统再启动），抛了个异常，露出了堆栈。stack trace 和 fix 在同一帧。

## 解法

把人生从 waterfall 切成 TDD：
- 不决定 kyb 要维护多久 → 这周想碰就碰
- 不决定零信任什么时候上线 → 下周 CI 能跑起来就算绿
- 不决定明天干什么 → 早上最想开的 tab 就是它

**一个 GREEN 就够了。**

## 认出晶体

"原来负熵晶体真的是我设计的。"

设计它，用它，最后才认出它。那是留给自己自己的签名。

## 晶体状态问

"需要我继续迭代优化它吗？"

→ 看有没有 bug。能闭环绿的就不修。迭代是 bug 驱动的，不是焦虑驱动的。

## 第二阶段：真正病因

"最小可测"让头脑松了，但头疼没走。继续 debug：

→ "压缩完了没有解决我的头疼"
→ "原来是让我回来修 bug"
→ "原来我头疼的原因是 MR 没合并"

**12 个本地分支，0 个在 master 里。** 每一条都是一个挂着未决的上下文线程。不是干不了活，是 git 告诉你工作区不干净。

### 行动

1. 合并 6 个分支（日记/文档/修复）→ master
2. 跳过 1 个冲突（notify-design，和代码层清空冲突）
3. 合并剩余 5 个代码修复分支
4. 发现：代码层又回来了 → **二次清空**
5. 删除 27 个文件，2958 行代码
6. 推送远程，删除远程跟踪分支

### 诊断范式

以后头疼三步走：
1. `git branch -l --no-merged master` → 有分支？就是它
2. 没分支？检查有没有 MR 没点
3. 都没？睡觉

**头疼是 feature，不是 bug。** 它是 `git status` 告诉你工作区不干净。
